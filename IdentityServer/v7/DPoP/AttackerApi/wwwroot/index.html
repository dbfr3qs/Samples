⚠️ OAuth DPoP Attack Demonstration

Warning: This is a security research tool to demonstrate potential vulnerabilities in OAuth DPoP implementations. Use only for educational purposes and authorized testing.

How the Attack Works

Step 1 (Attacker): Attacker starts OAuth flow, intercepts their own DPoP proof before it reaches the authorize endpoint, and exfiltrates it to the attacker API.
Step 2 (Victim): Victim's browser (compromised with malicious JS) polls the attacker API and receives the stolen DPoP proof.
Step 3 (Victim): Victim's browser initiates a silent OAuth flow in an invisible iframe, injecting the stolen DPoP proof.
Step 4 (Victim): After receiving the authorization code from the server, the victim's browser intercepts it and sends it to the attacker API.
Step 5 (Attacker): Attacker retrieves the stolen authorization code and uses it to complete their OAuth flow, gaining unauthorized access.
